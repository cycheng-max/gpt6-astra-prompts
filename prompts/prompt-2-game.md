使用剛剛完成的 3D 模型，將它改造成一個可在瀏覽器執行的 isometric 互動式 3D 小遊戲。

專案名稱：
{{project_slug}}

核心概念：
以「{{物件名稱}}」作為地基 / 主體，將它的頂部或主要表面改造成一個可探索的小場景，風格為 {{場景風格}}。

請直接操作我的電腦完成，不要只提供說明。

功能需求：
1. 使用 Three.js + React 建立一個可執行的單頁互動作品。
   模型請載入 Prompt 1 產出的 .glb（GLTFLoader）。若手上只有 .blend / .fbx，
   先轉成符合 Prompt 1【資產規格】的 .glb 再載入，不要直接載 .fbx。
2. 場景主體必須保留原本 {{物件名稱}} 的辨識特徵，讓人看得出是由該物件改造而成。
3. 在主體上方建立一個小型場景，內容包含：
   - 小攤位 / 小店 / 裝飾物
   - 遮陽棚或棚架
   - 路燈 / 招牌 / 小型場景道具
   - 至少 2–3 個 NPC
   - 一個可控制的小角色
4. 視角採 isometric 或近似等角視角，畫面清楚易讀。
5. 玩家操作：
   - WASD 移動
   - 鏡頭固定或輕微跟隨
   - 靠近 NPC 時按 E 可互動
6. NPC 互動：
   - 靠近時顯示提示「Press E」
   - 按下 E 後顯示簡單對話框
   - 每個 NPC 至少有 1 句不同台詞
7. 頁面需求：
   - 啟動後可直接執行
   - 載入畫面簡潔
   - 介面包含標題
   - 畫面上有簡單操作說明
8. 請整理專案結構，包含：
   - React 前端程式
   - Three.js 場景邏輯
   - 模型載入
   - 角色控制
   - NPC 互動
   - 基本樣式
9. 產出結果：
   - 可直接執行的專案
   - 單一 HTML 版本（若可行）
   - 或標準 React 專案結構
   - README，寫明啟動方式
10. 請在下方【安裝與執行授權】的範圍內完成安裝、開發、測試與修正，
    直到能正常開啟、移動角色與 NPC 互動。

美術方向：
- 保留原物件外觀辨識度
- 場景比例可愛化、迷你化
- 整體乾淨、可讀、不要過度雜亂
- 色彩風格統一，帶有 {{場景風格}} 的氛圍

【效能驗收】（硬性，量到數字才算通過）
- 面數：整個場景 ≤ 200,000 三角面
- 桌機 Chrome ≥ 60 fps；中階手機 ≥ 30 fps
- 首次可見畫面 ≤ 3 秒（以 4G 節流模擬）
- console error = 0；loader warning = 0（缺貼圖、缺材質都算失敗）
交付前請實際量測並回報數字，不要只宣稱通過。

【安裝與執行授權】（上限，不可自行放寬）
- 只能在專案目錄內安裝。不得 global install，不得使用 sudo 或系統管理員權限。
- 新增任何依賴前，先列出套件名、版本、用途，等我確認後再裝。
- 不修改專案目錄以外的任何檔案。
- 網路只允許連 npm registry 與我指定的資產來源。
- 「自行排除問題」的上限：同一個問題嘗試三次仍未解決就停下來回報，
  附完整錯誤訊息與你試過的三種做法，不要繼續無限重試。

品質標準：
- 一打開就能在瀏覽器看到完整場景
- 角色可移動
- 至少 2–3 個 NPC 可互動
- 場景與原始模型有明確關聯
- 沒有明顯 console error
- README 可讓人重現執行

錯誤處理：
- 若原始模型過重，請自行做合理優化（例如減面、合併、簡化碰撞）
- 若某些材質在 Web 端過重，請改用較輕量的替代方案
- 若單一 HTML 難以穩定封裝，請優先交付可正常執行的 React 專案，並在 README 說明限制
