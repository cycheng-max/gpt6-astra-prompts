1 照片 → Blender 高精度模型

必拍：正面/背面/左右/頂底/四斜角 + 接口/材質特寫 + 尺/硬幣

你現在要直接操作我的電腦，根據我提供的多張照片，在 Blender 4.4 中重建一個高精度 3D 模型。

目標物件：{{物件名稱}}

工作目標：
根據所有照片，建立一個外觀高度一致、比例正確、可後續編輯與匯出的 PBR 3D 模型，並輸出 Blender 原始檔與 FBX。

執行要求：
1. 先完整檢視所有照片，辨識物件的整體外形、尺寸比例、材質、接口、按鍵、孔位、結構分件與細節。
2. 若照片中有尺度參考物，請用它建立接近真實尺寸的比例；若沒有明確尺度參考，請先依照片估計比例，並在結果紀錄中明確標示「尺寸為估計值，非實測 1:1」。
3. 在 Blender 4.4 中建立乾淨、可編輯的模型：
   - 拓樸盡量規整
   - 物件命名清楚
   - 零件分層合理
   - 原點與座標整理好
4. 盡可能還原以下內容：
   - 整體外觀輪廓
   - 正面 / 背面 / 側面細節
   - 所有可見接口、孔位、按鍵、縫線、凹槽、散熱孔
   - 材質質感（如金屬、塑膠、霧面、亮面、磨砂、沖孔網格）
   - 發光區域、Logo、標示位置
5. 如背面接口可從照片辨識，請建模其外觀；若針腳細節在照片清楚可見，請盡量重建；若看不清楚，不要亂補，請保留合理簡化版本並在紀錄中標示哪些細節無法驗證。
6. 建立基本 PBR 材質：
   - Base Color
   - Roughness
   - Metallic
   - Normal / Bump（若適合）
   - Emission（若有發光區域）
7. 建立一個對照展示場景：
   - 中性背景
   - 至少 4 個視角渲染圖
   - 盡量模擬實拍角度，方便比對
8. 輸出以下檔案：
   - .blend（可編輯原始檔）
   - .glb（glTF 2.0 binary，供 Web 使用，必須符合下方【資產規格】）
   - .fbx（相容用途）
   - 預覽渲染圖（PNG）
   - 一份工作紀錄 markdown 或 txt，記錄：
     - 開始與完成時間
     - 主要步驟
     - 尺寸是否有實際依據
     - 哪些細節是高信心還原
     - 哪些細節因照片不足只能估計
9. 請在下方【安裝與執行授權】的範圍內直接執行，不要只告訴我做法。

【安裝與執行授權】（上限，不可自行放寬）
- 只能在指定的專案／輸出目錄內建立與修改檔案。不得修改該目錄以外的任何檔案。
- 不得使用系統管理員或 sudo 權限。不得做系統層級的安裝或設定變更。
- 需要安裝 Blender 外掛、Python 套件或任何額外元件前，先列出名稱、版本、
  來源與用途，等我確認後再裝。
- 網路只允許連 Blender 官方與我指定的素材來源。不要下載來路不明的檔案或腳本。
- 「自行排除障礙」的上限：同一個問題嘗試三次仍未解決就停下來回報，
  附完整錯誤訊息與你試過的三種做法，不要繼續無限重試。

【資產規格】（硬性，不符合就算未完成）
- 格式：glTF 2.0 binary（.glb），Y-up，單位公尺，原點在物件底部中心
- 面數：主物件 ≤ 50,000 三角面
- 貼圖：≤ 2048×2048，PBR 三張（baseColor / normal / metallicRoughness），
  不要輸出 .psd 或未合併的圖層
- 檔案：單一 .glb ≤ 10 MB，啟用 Draco 或 meshopt 壓縮
- 尺寸：邊界框長寬高與參考尺寸誤差 ≤ 5%；無尺度參考物時標明「非實測 1:1」，
  此時不適用這條誤差要求
輸出後請自行以上述每一項逐條檢查，並把實際數值（面數、貼圖尺寸、檔案大小、
邊界框尺寸）寫進工作紀錄，不要只寫「已完成」。

品質標準：
- 外觀輪廓與照片一致
- 各面主要細節不可漏掉
- 模型比例自然，不可明顯變形
- 材質方向正確
- 匯出檔案可正常開啟
- 結果必須包含可比對的渲染圖與工作紀錄

錯誤處理：
- 若照片不足以確認某區域，請根據最接近的視角做保守重建，並在紀錄中標示為「推測」。
- 若某些文字、Logo、針腳、紋理看不清楚，不要虛構，請做可辨識程度內的合理近似。
- 若無法確認真實尺寸，請明確標示「非實測 1:1」。

2 模型 → 可玩的 3D 小遊戲

Three.js + React / Isometric / WASD + E

使用剛剛完成的 3D 模型，將它改造成一個可在瀏覽器執行的 isometric 互動式 3D 小遊戲。

專案名稱：
{{project_slug}}

核心概念：
以「{{物件名稱}}」作為地基 / 主體，將它的頂部或主要表面改造成一個可探索的小場景，風格為 {{場景風格}}。

請直接操作我的電腦完成，不要只提供說明。

功能需求：
1. 使用 Three.js + React 建立一個可執行的單頁互動作品。
   模型請載入 Prompt 1 產出的 .glb（GLTFLoader）。若手上只有 .blend / .fbx，
   先轉成符合 Prompt 1【資產規格】的 .glb 再載入，不要直接載 .fbx。
2. 場景主體必須保留原本 {{物件名稱}} 的辨識特徵，讓人看得出是由該物件改造而成。
3. 在主體上方建立一個小型場景，內容包含：
   - 小攤位 / 小店 / 裝飾物
   - 遮陽棚或棚架
   - 路燈 / 招牌 / 小型場景道具
   - 至少 2–3 個 NPC
   - 一個可控制的小角色
4. 視角採 isometric 或近似等角視角，畫面清楚易讀。
5. 玩家操作：
   - WASD 移動
   - 鏡頭固定或輕微跟隨
   - 靠近 NPC 時按 E 可互動
6. NPC 互動：
   - 靠近時顯示提示「Press E」
   - 按下 E 後顯示簡單對話框
   - 每個 NPC 至少有 1 句不同台詞
7. 頁面需求：
   - 啟動後可直接執行
   - 載入畫面簡潔
   - 介面包含標題
   - 畫面上有簡單操作說明
8. 請整理專案結構，包含：
   - React 前端程式
   - Three.js 場景邏輯
   - 模型載入
   - 角色控制
   - NPC 互動
   - 基本樣式
9. 產出結果：
   - 可直接執行的專案
   - 單一 HTML 版本（若可行）
   - 或標準 React 專案結構
   - README，寫明啟動方式
10. 請在下方【安裝與執行授權】的範圍內完成安裝、開發、測試與修正，
    直到能正常開啟、移動角色與 NPC 互動。

美術方向：
- 保留原物件外觀辨識度
- 場景比例可愛化、迷你化
- 整體乾淨、可讀、不要過度雜亂
- 色彩風格統一，帶有 {{場景風格}} 的氛圍

【效能驗收】（硬性，量到數字才算通過）
- 面數：整個場景 ≤ 200,000 三角面
- 桌機 Chrome ≥ 60 fps；中階手機 ≥ 30 fps
- 首次可見畫面 ≤ 3 秒（以 4G 節流模擬）
- console error = 0；loader warning = 0（缺貼圖、缺材質都算失敗）
交付前請實際量測並回報數字，不要只宣稱通過。

【安裝與執行授權】（上限，不可自行放寬）
- 只能在專案目錄內安裝。不得 global install，不得使用 sudo 或系統管理員權限。
- 新增任何依賴前，先列出套件名、版本、用途，等我確認後再裝。
- 不修改專案目錄以外的任何檔案。
- 網路只允許連 npm registry 與我指定的資產來源。
- 「自行排除問題」的上限：同一個問題嘗試三次仍未解決就停下來回報，
  附完整錯誤訊息與你試過的三種做法，不要繼續無限重試。

品質標準：
- 一打開就能在瀏覽器看到完整場景
- 角色可移動
- 至少 2–3 個 NPC 可互動
- 場景與原始模型有明確關聯
- 沒有明顯 console error
- README 可讓人重現執行

錯誤處理：
- 若原始模型過重，請自行做合理優化（例如減面、合併、簡化碰撞）
- 若某些材質在 Web 端過重，請改用較輕量的替代方案
- 若單一 HTML 難以穩定封裝，請優先交付可正常執行的 React 專案，並在 README 說明限制
